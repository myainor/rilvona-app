## About

Rilvona is a free, open-source app for university students. It reads your data from the university portal and shows it the way it should have been shown, then does the planning for you: how many classes you can still skip, where your attendance will land by a given date, and what to attend to stay safe. It also has a campus community with hives, posts, events and anonymous questions.

> Rilvona is an independent app for students. It is not owned, run, sponsored or endorsed by Chandigarh University.

## Features

- **Live attendance**: subject by subject, with how many classes you can still skip
- **Class planner**: predict your attendance to any date and see what to attend
- **Timetable**: today's classes with room and teacher, and a live "class now" card
- **Marks and results**, **date sheet** with a countdown, and the **academic calendar**
- **AI study assistant** that answers from your own data
- **Virtual ID card** on your phone
- **Campus community**: hives, posts, events and anonymous questions
- **Private by design**: sign in with Google, and your university password stays in your phone's secure keychain

## Download

Rilvona is distributed as a direct APK, not through the Play Store. Get the latest release, with its SHA-256 checksum and install steps, at **[rilvona.com](https://rilvona.com/#download)**.

1. Open [rilvona.com](https://rilvona.com/#download) on your Android phone (Android 7.0 or newer) and tap **Download APK**.
2. Open the file. If Android asks, allow installs from your browser.
3. Tap **Install**, then **Open**.

Optionally verify the file with `shasum -a 256 rilvona-<version>.apk` against the checksum on the site. Installing an APK from outside the Play Store may show a Play Protect notice.

## Tech stack

TypeScript everywhere except the AI service: a [NestJS](https://nestjs.com) API with [Prisma](https://www.prisma.io), PostgreSQL and Redis; a [React Native](https://reactnative.dev) app; a small Python [FastAPI](https://fastapi.tiangolo.com) service for AI features; and a static site generated by a small Node script.

## Layout

| Path | What it is |
| --- | --- |
| `apps/api` | NestJS + Prisma API (PostgreSQL, Redis) served at `/api/v1` |
| `apps/mobile` | React Native app (Android today; iOS is [planned](https://github.com/myainor/rilvona-app/issues/7)) |
| `apps/ai` | Small FastAPI service the API calls for AI features (Mistral) |
| `apps/site` | The [rilvona.com](https://rilvona.com) landing page and APK downloads (`node build.mjs`) |
| `packages/contracts` | Shared types and schemas used by the API |

## Requirements

- Node.js 24 (see `.nvmrc`; `>=22.11` works)
- PostgreSQL and Redis
- Python 3.11+ for `apps/ai` (optional)
- Android Studio (JDK 17) for the mobile app

## Run the API

```sh
npm install
cp apps/api/.env.example apps/api/.env   # then set the secrets
npm run prisma:migrate
npm run seed                             # optional, needs SEED_ADMIN_* in .env
npm run dev:api
```

Run the tests with `npm test`. Production settings are listed in `apps/api/.env.production.example`.

## Run the AI service (optional)

```sh
cd apps/ai
python -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env                     # set AI_SERVICE_KEY and MISTRAL_API_KEY
./run.sh
```

## Run the mobile app

```sh
npm run mobile:install
npm run mobile:start
npm run mobile:android
```

The app talks to the hosted API by default. Before developing against your own API,set `API_ORIGIN` in `apps/mobile/src/config.local.ts` (see `apps/mobile/src/config.local.example.ts`)` and set your own Google sign-in client IDs there. Be careful not to run a debug build against production data you don't want to change.

To sign a release build, create `~/hiihive-signing/keystore.properties` (or point `HIIHIVE_KEYSTORE_PROPERTIES` at another file) with `storeFile`, `storePassword`, `keyAlias`, and `keyPassword`. It lives outside the repo, and all keystores are gitignored. Without it, release builds fall back to the debug key.

## Website and APK downloads

`apps/site` is the landing page at [rilvona.com](https://rilvona.com). The Android app is distributed as a self-hosted APK instead of through the Play Store.

```sh
# 1. Build a signed APK (arm64 and armv7 keep it small)
cd apps/mobile/android && ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a,armeabi-v7a

# 2. Record its version, size and SHA-256 in apps/site/release.json and stage it for upload
cd ../../site && node publish-apk.mjs ../mobile/android/app/build/outputs/apk/release/app-release.apk

# 3. Upload the APK to /download/ and publish the site
DEPLOY_HOST=user@your-server ./deploy.sh
```

The download button links to the versioned file (`/download/rilvona-<version>.apk`); `/download/rilvona.apk` always points to the latest. The server needs a `/download/` location that serves `.apk` as `application/vnd.android.package-archive`. Commit the updated `release.json` after each release. Keep the signing key safe: updates only install over an existing app when signed with the same key.

## Contributing

**We are accepting open-source contributions.** Rilvona is built by students, for students, and help from anyone who has ever fought with a university portal is welcome.

- Start with the [good first issues](https://github.com/myainor/rilvona-app/issues?q=is%3Aissue+is%3Aopen+label%3A%22good+first+issue%22) or the [open bugs](https://github.com/myainor/rilvona-app/issues?q=is%3Aissue+is%3Aopen+label%3Abug).
- Have an idea? [Open an issue](https://github.com/myainor/rilvona-app/issues/new) and describe the problem it solves.
- Fork the repo, create a branch, and open a pull request. Run `npm test` and `npm run mobile:test` first.
- Never commit `.env` files, keystores, or OAuth client secrets. When reporting portal bugs, do not paste student IDs, cookies, passwords or portal HTML into issues; redact them first.
